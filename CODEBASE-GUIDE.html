01 What the app does

  • Problem: Flatmates waste 15–20 minutes every single day debating what to cook, checking pantry ingredients manually, and haggling over dinner choices.
  • Solution: A single shared web application where the flat votes on curated meal suggestions with automated grocery shortfall calculation.
  • Goal: Daily meal decision made in under 2 minutes.
  • App name shown to users: "Aaj Kya Banega?" ("What will be made today?")

The Complete Daily Loop

1. Login / Sign up (Email+Password or Google OAuth)
   ↓
2. Join an existing flat via 6-char Invite Code OR Create a new Flat
   ↓
3. Pantry Management: Add ingredients manually or parse free text ("bought 2kg potatoes...") via Gemini AI
   ↓
4. Daily Session: First load of the day creates "lunch" & "dinner" sessions (locked to flat's timezone)
   ↓
5. AI Suggestion: Gemini 2.5 Flash suggests 5 budget Indian dishes matching in-stock ingredients & avoiding recent 10 meals
   ↓
6. Flat Voting: Live optimistic voting (polling every 8s) where flatmates vote / change votes
   ↓
7. Admin Finalization: Admin tallies within a locked SQL transaction (ties broken by earliest suggestion)
   ↓
8. Grocery Shortfall: Missing ingredients for the winning dish are automatically computed as a copyable shopping list

04 The 3-Layer Rule & Complete Server Actions Registry

The fundamental architectural pillar: strict separation of UI, orchestration, and business logic.

components/   →  UI Only (React 19). Calls Server Actions via useTransition / useActionState.
     ↓
app/*/actions →  Orchestration: Verifies session & permissions, parses FormData, handles cache revalidation.
     ↓
lib/          →  Pure Domain Logic: Framework-free TypeScript. Interacts directly with Drizzle ORM.
     ↓
db/           →  Drizzle Schema & Neon Postgres connection.
  • Strict Prohibition: src/lib/ is strictly forbidden from importing anything from next/* (e.g. next/navigation, next/headers, next/cache).
  • Portability: This ensures all domain functions can be tested in pure Node/Vitest or extracted into a standalone worker/microservice without rewriting database interactions.
  • Enforced by CI: src/lib/architecture.test.ts scans all files in src/lib/ on every build and fails if any next import is discovered.

06 How Authentication Works (In-Depth)

Dual-layer authentication combining lightweight Edge decryption with authoritative Server-side database version checking.

JWT Session Payload Specification

Tokens are signed with AUTH_SECRET using HS256. Every issued token encapsulates:

{
  "sub": "user_12345678-uuid",       // Unique users.id
  "name": "Arjun Sharma",            // Display name
  "email": "arjun@example.com",      // Confirmed email
  "token_version": 2,                // Stamped version from users.token_version
  "email_verified": "2026-10-14...", // Timestamp of verification
  "iat": 1728920000,                 // Issued at
  "exp": 1729524800                  // 7-day expiration (604,800 seconds)
}

Revoking Stateless Sessions (Token Versioning)

Because JWTs are stateless and self-contained, standard JWT setups cannot revoke a single stolen session cookie without invalidating the global secret key. Flatmate solves this via Token Versioning in src/lib/auth-state.ts:

  1. Every user has an integer users.token_version (default 0) in Postgres.
  2. When signing in, this version number is stamped directly into the JWT payload.
  3. On every incoming request, auth() extracts the stamped version and compares it against the active version stored in Redis cache (auth:${userId}, TTL 300s).
  4. If Redis misses or is disabled, it reads users.token_version from Postgres and repopulates Redis.
  5. Session Revocation ("Sign out everywhere"): Running revokeUserSessions(userId) executes: 
    UPDATE users SET token_version = token_version + 1 WHERE id = $1 RETURNING token_version;
    And immediately writes the new version through to Redis. All previously issued tokens on all devices immediately fail on their very next request!

Email Verification Security Architecture

  • SHA-256 Token Storage: When a user signs up or requests a link, 32 cryptographic random bytes are generated (crypto.randomBytes(32).toString('hex')). Only the SHA-256 hash is stored in verification_tokens(identifier, token, expires). Even a total database dump exposes zero active verification links.
  • Public Landing: /verify?token=...&email=... is intentionally public so a flatmate clicking the link on a desktop can confirm the account created on their phone without being logged in on the desktop.
  • Account Hijack Prevention: allowDangerousEmailAccountLinking is explicitly disabled on Google OAuth. If an attacker registers a target's email with a password, a subsequent Google sign-in by the real owner does not merge accounts. Furthermore, Google's email_verified boolean claim is strictly checked.

07 Route Protection Architecture

Multi-tiered defensive gating from edge proxy down to individual server actions.

Tier 1: Edge Proxy (src/proxy.ts)

Next.js 16 replaces traditional middleware.ts with proxy.ts (must export a function named proxy). It evaluates protected route prefixes: /dashboard, /pantry, /history, /settings, /onboarding, and /verify-email.

Tier 2: Protected Layout Gate (src/app/(protected)/layout.tsx)

  1. Authentication Check: session?.user present? If NO → redirect to /login.
  2. Email Verification Check: session.user.emailConfirmed is true? If NO → redirect to /verify-email. Unverified users cannot view flat data.
  3. Group Membership Check: User belongs to an active flat in group_members? If NO → redirect to /onboarding to create or join a group.

Tier 3: Mandatory Server Action Guards: A client can dispatch a POST request directly to a Server Action endpoint bypassing layout render cycles. Therefore, every single Server Action in app/*/actions.ts independently invokes auth(), asserts email confirmation, and validates group ownership before executing any database mutation.

Powered by gemini-2.5-flash via REST API with a 15-second timeout and JSON response schema enforcement.

2. Natural Language Pantry Parsing

Flatmates can paste unstructured receipts or chat messages like: "Got 2kg potatoes, 500g paneer, 1 bunch coriander and a pack of bread".

  • Gemini parses into structured objects: [{ name: "potato", quantity: 2, unit: "kg" }, { name: "paneer", quantity: 500, unit: "g" }].
  • Intelligent Merging (src/lib/pantry/merge.ts):
    • If unit matches existing inventory (e.g. both "kg") → quantities are automatically added.
    • If units conflict (e.g. existing "bunch" vs incoming "kg") → incoming entry replaces existing stock.
    • If item doesn't exist → status is flagged as new.

3. Optimistic Voting & Realtime Polling

  • Optimistic UI: Tapping a meal instantly flips UI state using React 19's useOptimistic, providing sub-16ms interactive response.
  • Tab-Aware Polling: The voting screen polls every 8 seconds via visibilitychange listeners — polling suspends when the tab is backgrounded, conserving mobile battery and server bandwidth. Polling automatically terminates once both lunch and dinner are finalized.

09 Concurrency & Race Condition Prevention

Because multiple flatmates interact simultaneously on their phones, all race vectors are hardened with database-level primitives.

Concurrency ScenarioPotential FailureArchitectural Fix & SQL Primitive
Morning Simultaneous Load Two flatmates open the app at 8:00 AM; two simultaneous session creation queries race. Unique partial index (group_id, session_date, meal_type) combined with ON CONFLICT DO NOTHING absorbs the collision cleanly.
Regenerate vs In-Flight Vote User A clicks "Regenerate" (deleting suggestions) exactly as User B submits a vote on Dish #3. replaceSuggestions executes inside a transaction acquiring a row lock: SELECT status FROM meal_sessions WHERE id = $1 FOR UPDATE. The session status flips to voting immediately when a vote lands, blocking suggestion deletion.
Finalization Mid-Vote Admin clicks Finalize while a flatmate changes their vote; tally becomes inconsistent. finalizeSessionForGroup runs within a transaction with row-level locking: SELECT * FROM meal_sessions FOR UPDATE. Tallying and status transition to finalized occur atomically.
AI Generation Spamming Multiple users spam the "Regenerate" button to trigger multiple costly Gemini calls. Atomic guarded SQL update: 
UPDATE meal_sessions 
SET last_generated_at = now() 
WHERE id = $1 AND status = 'open' 
  AND (last_generated_at IS NULL OR last_generated_at < now() - interval '30 seconds') 
RETURNING id;
Only the winner of this atomic update receives a returned row; losers receive an instant cooldown error before any AI call is made.
Invite Code Collision Random 6-character code matches an existing active group. Unique constraint on groups.invite_code caught by isUniqueViolation error handler; automatically retries generation with exponential backoff up to 5 times.

    • /pantry and /history are aggressively prefetched in the background so navigating to them is instantaneous with zero skeleton screens.
    • /dashboard is deliberately NOT prefetched. Pre-rendering cached voting states would display stale vote counts and risk cooking the wrong meal!

16 Things to Remember Before Editing

⚠️ Next.js 16 Breaking Conventions: Read node_modules/next/dist/docs/ before editing core routes. Middleware is now configured via proxy.ts exporting proxy. Server Actions are strictly isolated callable endpoints.

  • The Lib Rule: Never import next inside src/lib/. If you need cache revalidation, put it in the calling Server Action inside src/app/.
  • Defense in Depth: Always re-verify session identity and group membership inside Server Actions — page layout redirects do not protect action POST endpoints.
  • Database Migrations: Never hand-write SQL files in drizzle/. Modify src/db/schema.ts and run npm run db:generate.
  • Cache Invalidation: Server actions modifying database rows must call revalidatePath("/dashboard") or revalidatePath("/pantry") so clients reflect fresh state.
  • AI Output Safety: Never trust Gemini JSON blindly. Always pipe model output through Zod parsers in src/lib/ai/parse.ts.
